# Smriti Project Context

## Current Goal
Keep the Android mock demo stable while making controlled LiteRT-LM runtime-readiness progress: Room uses KSP, `EngineConfig` construction works, Engine initialization is manual-only, and text-only LiteRT inference exists only behind an explicit manual method.

The repository has a working Android Kotlin + Jetpack Compose offline field-tool prototype, with `MockGemmaAgent` still configured as the default and `RealGemmaAgent` still experimental. The official LiteRT-LM Android dependency is pinned to `0.10.2`. Room annotation processing has migrated from KAPT to KSP `2.3.7`; no `kapt` Gradle dependency or KAPT task remains. Direct references to `Engine`, `EngineConfig`, `Backend`, `Content.Text`, and `Conversation` compile through `LiteRtApiSurfaceProbe`. `LiteRtEngineConfigFactory` constructs a real LiteRT `EngineConfig` with `Backend.CPU()` only when `ModelAvailability` reports `FOUND_NOT_LOADED`; `NOT_FOUND` still returns no config. `LiteRtEngineInitializationChecker` can instantiate `Engine` only when a found model, a prepared config, and `allowManualEngineInitialization=true` are all provided; it calls `initialize()` inside `use {}` so `Engine.close()` runs immediately. `LiteRtGemmaTextClient.generateText(...)` still returns unavailable by default. `LiteRtGemmaTextClient.generateTextManual(...)` is the only text inference path: it requires `allowManualTextInference=true`, a found model, and prepared `EngineConfig`; it runs on `Dispatchers.IO` inside `withTimeout`, creates `Engine`, initializes it, creates one `Conversation`, calls `sendMessage(prompt)`, extracts `Content.Text`, then closes Conversation and Engine via `use {}`. Developer-only instrumentation tests can invoke that path with a sideloaded model and explicit instrumentation argument: `ManualLiteRtTextInferenceInstrumentedTest` sends the non-clinical prompt `Reply with exactly: SMRITI_LITERT_OK`, and `ManualRealGemmaVisitJsonInstrumentedTest` sends a realistic Meena ANC visit prompt built with `RealGemmaPromptBuilder`, logs raw output, and parses it with `RealGemmaOutputParser`. These manual tests never touch Room patient/visit data. This manual path is not wired into app startup, Patient Roster, VisitScreen, ReviewScreen, SummaryScreen, or any visible toggle. Offline Proof remains visible from both the patient roster and supervisor summary through shared `OfflineProofStatus`/`OfflineProofCard` data, with `EngineConfig: Ready when model found; Engine manual-only` and `Inference: Disabled by default; manual-only`. `RealGemmaReadinessEvaluator` remains the safety decision layer and every current readiness summary has `modelLoadingAllowed=false`, `inferenceAllowed=false`, and `demoSafe=true`. RealGemma has a text-only execution scaffold, but the default text client is unavailable and the normal app factory remains mock. `LiteRtModelPaths` is the single source of truth for `filesDir/models/gemma-4-E2B-it-int4.litertlm`. `.gitignore` and a unit repo-safety test guard against committed `.litertlm`, `.task`, `.tflite`, and `.onnx` artifacts. No model files, model downloads, audio/Gemma path, Hugging Face runtime code, visible UI toggle, function calling, or normal app-flow inference changes were added.

## Architecture Decisions
- Build Android native with Kotlin and Jetpack Compose to match the PRD and demo needs.
- Keep all MVP core behavior offline with local mock data and no network APIs.
- Put Gemma behavior behind a `GemmaAgent` interface so LiteRT-LM can replace `MockGemmaAgent` later.
- Keep `MockGemmaAgent` as the default demo-safe mode via `AgentConfig.DEFAULT_MODE = AgentMode.MOCK`.
- Keep `RealGemmaAgent` as a safe stub until LiteRT-LM model loading and structured parsing are proven.
- Use LiteRT-LM via a local filesystem `.litertlm` model path when the real integration begins; prefer app-private sideload/import for the multi-GB model and keep model files out of git.
- Treat the first LiteRT-LM dependency addition as a compatibility validation step only; do not enable inference or model loading until a separate model availability/load spike.
- Keep model availability separate from model loading: app-private file presence may be shown in Offline Proof, but `FOUND_NOT_LOADED` must still mean inference is disabled.
- Keep RealGemma text-only execution behind an injectable `RealGemmaTextClient`: prompt building and output parsing can be tested locally before any LiteRT-LM engine call is introduced.
- Keep LiteRT-backed text generation behind a disabled `LiteRtGemmaTextClient`; `EngineConfig` may be constructed, but Engine initialization remains manual-only and inference remains disabled.
- Keep manual text inference behind explicit method calls only; do not wire it into app startup, normal UI, or the default `GemmaAgentFactory`.
- Keep `LiteRtEngineInitializationChecker` out of normal UI/app startup; only a separate approved/manual model-loading check may instantiate `Engine`.
- Keep `RealGemmaReadinessEvaluator` as the only readiness/activation decision layer; it documents why RealGemma is blocked or disabled without adding an activation switch.
- Use Kotlin 2.3.10 with the matching `org.jetbrains.kotlin.plugin.compose` Compose compiler Gradle plugin instead of the older `composeOptions.kotlinCompilerExtensionVersion` path.
- Use AGP 8.13.2 and Gradle 8.13 because Android's Kotlin support table requires AGP 8.13.2 for Kotlin 2.3.
- Use Room 2.8.4 so Room's annotation processor can handle newer Kotlin metadata from the upgraded toolchain and LiteRT-LM dependencies.
- Use KSP 2.3.7 for Room annotation processing; the app module no longer applies the Kotlin KAPT plugin.
- Implement text-only `RealGemmaAgent` before attempting direct audio input so prompt construction, protocol citation validation, JSON parsing, timeout handling, and `MockGemmaAgent` fallback are proven first.
- Use Room entities/DAOs as the local persistence boundary and seed demo data on first app launch.
- Use a simple in-app screen state machine instead of adding Navigation Compose for the first scaffold.
- Use a flat keyword `ProtocolRetriever` for protocol chunks until the P1 local RAG corpus is added.
