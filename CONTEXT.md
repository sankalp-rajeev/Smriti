Direct references to `Engine`, `EngineConfig`, `Backend`, `Content.Text`, `Conversation`, `ConversationConfig`, `OpenApiTool`, `ToolCall`, `Content.AudioBytes`, `Content.AudioFile`, and `InputData.Audio` compile through `LiteRtApiSurfaceProbe`. `LiteRtEngineConfigFactory` constructs a real LiteRT `EngineConfig` with `Backend.CPU()` only when `ModelAvailability` reports `FOUND_NOT_LOADED`; `NOT_FOUND` still returns no config. `LiteRtEngineInitializationChecker` can instantiate `Engine` only when a found model, a prepared config, and `allowManualEngineInitialization=true` are all provided; it calls `initialize()` inside `use {}` so `Engine.close()` runs immediately. `LiteRtGemmaTextClient.generateText(...)` still returns unavailable by default. `LiteRtGemmaTextClient.generateTextManual(...)` is the explicit text inference path: it requires `allowManualTextInference=true`, a found model, and prepared `EngineConfig`; it runs on `Dispatchers.IO` inside `withTimeout`, creates `Engine`, initializes it, creates one `Conversation`, calls `sendMessage(prompt)`, extracts `Content.Text`, then closes Conversation and Engine via `use {}`. Developer-only instrumentation tests can invoke that path with a sideloaded model and explicit instrumentation argument: `ManualLiteRtTextInferenceInstrumentedTest` sends the non-clinical prompt `Reply with exactly: SMRITI_LITERT_OK`; `ManualRealGemmaVisitJsonInstrumentedTest` sends a realistic Meena ANC visit prompt built with `RealGemmaPromptBuilder`, logs raw output, and parses it with `RealGemmaOutputParser`; `ManualRealGemmaAgentInstrumentedTest` constructs `RealGemmaAgent` with an androidTest-only adapter backed by `LiteRtGemmaTextClient.generateTextManual(...)` to verify the full prompt-builder -> LiteRT manual inference -> parser -> `VisitReasoningResult` path; `ManualRealGemmaBenchmarkInstrumentedTest` runs three manual RealGemmaAgent scenarios and logs prompt length, raw output length, raw protocol citation, single-citation contract adherence, parser success, referral/citation/safety/uncertainty flags, latency, and aggregate summary metrics; `ManualRealGemmaMemoryStressInstrumentedTest` runs 10/20/40 synthetic prior-visit context sizes and logs prompt, latency, parser, safety, and approximate JVM memory metrics. `ManualLiteRtFunctionCallingInstrumentedTest` is a real native tool-call probe using `OpenApiTool` and `ConversationConfig(tools=..., automaticToolCalling=true)`; JSON prompting remains the safe fallback until that probe proves reliable on-device. `ManualLiteRtAudioCapabilityInstrumentedTest` logs the exposed audio API surface and preprocessing findings only; `ManualLiteRtAudioInferenceInstrumentedTest` is the separate manual real-audio runtime probe and now reports blocked/skipped if LiteRT-LM still requires an unavailable preprocessing step. `RealGemmaPromptBuilder` now gives a stricter citation contract: choose exactly one supplied citation, never join citations, use the single primary/urgent citation, and emit an empty `protocolCitation` with `uncertain=true` when no protocol chunk is supplied; it also supports `maxHistoryVisits` for manual memory stress while keeping the default at five. `ProtocolCitationValidator` enforces that parsed model output uses either exactly one supplied citation or an empty no-protocol uncertain citation; it rejects invented citations, semicolon-joined citations, and model-written "No matching protocol citation". `RealGemmaAgent` applies `RealGemmaSafetyPostProcessor` after successful parser output so the structured note always includes "This is not a diagnosis." and "CHW confirmation is required before saving." without relying on model wording; parser diagnostic-language rejection remains unchanged. These manual tests never touch Room patient/visit/referral data. Phase 3 added developer-only RealGemma text UI mode behind both a build-time gate and an app-private local sentinel file, with the app-private model also required before inference can run; this is not the default demo path and has no public CHW-facing toggle. Offline Proof remains visible from both the patient roster and supervisor summary through shared `OfflineProofStatus`/`OfflineProofCard` data, with local Room/SQLite patient data, local JSON country-aware protocols, default mock mode, RealGemma model status, inference disabled by default, and direct Gemma audio blocked with offline speech/transcript fallback. `RealGemmaReadinessEvaluator` remains a safety decision layer. `LiteRtModelPaths` is the single source of truth for `filesDir/models/gemma-4-E2B-it-int4.litertlm`. `.gitignore` and a unit repo-safety test guard against committed `.litertlm`, `.task`, `.tflite`, and `.onnx` artifacts. No model files, model downloads, large audio files, audio/Gemma app-flow wiring, Hugging Face runtime code, public RealGemma toggle, function calling in normal flow, or default app-flow inference changes were added.

## Architecture Decisions
- Build Android native with Kotlin and Jetpack Compose to match the PRD and demo needs.
- Keep all MVP core behavior offline with local mock data and no network APIs.
- Put Gemma behavior behind a `GemmaAgent` interface so LiteRT-LM can replace `MockGemmaAgent` later.
- Keep `MockGemmaAgent` as the default demo-safe mode via `AgentConfig.DEFAULT_MODE = AgentMode.MOCK`.
- Keep `RealGemmaAgent` as a safe stub until LiteRT-LM model loading and structured parsing are proven.
- Use LiteRT-LM via a local filesystem `.litertlm` model path when the real integration begins; prefer app-private sideload/import for the multi-GB model and keep model files out of git.
- Treat the first LiteRT-LM dependency addition as a compatibility validation step only; do not enable inference or model loading until a separate model availability/load spike.
- Keep model availability separate from model loading: app-private file presence may be shown in Offline Proof, but `FOUND_NOT_LOADED` must still mean inference is disabled.
- Keep RealGemma text-only execution behind an injectable `RealGemmaTextClient`: prompt building and output parsing can be tested locally before any LiteRT-LM engine call is introduced.
- Keep LiteRT-backed text generation behind a disabled `LiteRtGemmaTextClient`; `EngineConfig` may be constructed, but Engine initialization remains manual-only and inference remains disabled.
- Keep manual text inference behind explicit method calls only; do not wire it into app startup, normal UI, or the default `GemmaAgentFactory`.
- Keep `LiteRtEngineInitializationChecker` out of normal UI/app startup; only a separate approved/manual model-loading check may instantiate `Engine`.
- Keep `RealGemmaReadinessEvaluator` as the only readiness/activation decision layer; it documents why RealGemma is blocked or disabled without adding an activation switch.
- Use Kotlin 2.3.10 with the matching `org.jetbrains.kotlin.plugin.compose` Compose compiler Gradle plugin instead of the older `composeOptions.kotlinCompilerExtensionVersion` path.
- Use AGP 8.13.2 and Gradle 8.13 because Android's Kotlin support table requires AGP 8.13.2 for Kotlin 2.3.
- Use Room 2.8.4 so Room's annotation processor can handle newer Kotlin metadata from the upgraded toolchain and LiteRT-LM dependencies.
- Use KSP 2.3.7 for Room annotation processing; the app module no longer applies the Kotlin KAPT plugin.
- Implement text-only `RealGemmaAgent` before attempting direct audio input so prompt construction, protocol citation validation, JSON parsing, timeout handling, and `MockGemmaAgent` fallback are proven first.
- Use Room entities/DAOs as the local persistence boundary and seed demo data on first app launch.
- Use a simple in-app screen state machine instead of adding Navigation Compose for the first scaffold.
